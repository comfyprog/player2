# player2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Linux terminal music player with MOC's filesystem-first two-pane workflow, broad FFmpeg-backed format support, and first-class CUE albums that appear as enterable folders with independently seekable tracks.

**Architecture:** Bubble Tea v2 TUI → queue/playback controller → FFmpeg subprocess decoder → PCM ring buffer → malgo audio output. Filesystem scanning, CUE parsing, metadata, playlists, and config are separate packages with no library database.

**Tech Stack:** Go 1.26, `charm.land/bubbletea/v2`, `charm.land/lipgloss/v2`, `charm.land/bubbles/v2` (text input), `github.com/gen2brain/malgo` (cgo audio output), `github.com/pelletier/go-toml/v2`, `golang.org/x/text`, system `ffmpeg` + `ffprobe`.

**Spec:** This document — the design was agreed in conversation and is inlined below; there is no separate spec file.

---

## 1. Non-negotiable behavior

- Linux TUI, keyboard-driven, MOC-like layout: browser left, playlist right, status/progress at the bottom.
- Filesystem-first navigation. No library index, database, daemon, or client/server split.
- No network access. FFmpeg is restricted with `-protocol_whitelist file`; playlist/CUE entries containing `http://`, `https://`, etc. are rejected.
- Supported formats come from FFmpeg. Default extension set includes MP3, OGG/Vorbis, Opus, FLAC, ALAC/M4A, APE, WavPack, WAV, AIFF, DSF/DFF, MKA, MPC, TTA, WMA, and others. New FFmpeg formats can be enabled by adding an extension or registering a decoder.
- A valid `.cue` whose referenced audio exists appears as an enterable folder. Its tracks are normal playlist items with independent start/end offsets and independent seeking.
- Invalid CUE sheets are shown as invalid entries and never hide the underlying audio.
- Playback is local files only.

**Explicit non-goals for v1:** gapless playback across separate items, library indexing, lyrics, visualizers, tag editing, cover art, scrobbling, ReplayGain, MPRIS, remote control, mouse support, Windows/macOS.

---

## 2. Decisions I made

1. **Decoding uses the `ffmpeg` CLI, not cgo libav bindings.** It is robust across FFmpeg versions and formats, keeps the decoder process isolated, and still sits behind a decoder interface. A future libavcodec backend can replace it without touching UI or playback.
2. **Audio output uses malgo/miniaudio.** Only cgo requirement; no ALSA headers needed at build time, and it supports PulseAudio/ALSA/JACK.
3. **Enter on an audio file plays the rest of that directory**, matching MOC's documented behavior. It replaces the playlist with the current location's playable entries and starts at the selection. CUE folders play their tracks the same way.
4. **Referenced audio files are hidden** when a valid CUE replaces them in the listing (`Album.flac` disappears, `Album.cue/` appears). This avoids duplicate album entries. Invalid CUEs hide nothing.
5. **Session queue persists as JSON**, because CUE tracks need offsets. User playlists use standard `.m3u`/`.m3u8`, with a small optional extension for CUE track references.
6. **No tag library.** Metadata and durations come from `ffprobe`; CUE metadata comes from the CUE sheet.
7. **Gapless is not promised in v1.** FFmpeg process startup may introduce a short gap between queue items. For CUE albums this is a known v1 limitation; the decoder interface leaves room for stream reuse later.

## 3. User-visible design

### Layout

```text
┌ player2 ─ ▶ Title — Artist ─ 1:23 / 4:12 ─ vol 70 ─ R:all S:off ┐
│ Files: ~/Music/Album.cue           │ Playlist (12)                 │
│ > 01. Opening — Artist      3:21   │   01. Opening — Artist  3:21  │
│   02. Theme — Artist        4:12   │ > 02. Theme — Artist    4:12  │
│   03. Finale — Artist       5:03   │   03. Finale — Artist   5:03  │
│                                    │                               │
├────────────────────────────────────┴───────────────────────────────┤
│ Status: ready                    [progress bar]                    │
│ ? help  tab pane  enter play  a add  space pause  / search  q quit  │
└────────────────────────────────────────────────────────────────────┘
```

- Fixed one-line header, two-pane body, two-line footer (status/progress + key hints).
- Focused pane title is accented; selection uses inverse/highlight; now-playing row is marked.
- Filenames are truncated with ellipsis, Unicode-width aware.
- `?` opens a two-column keybinding overlay; `Esc` closes.
- Minimum terminal size 60×10; below that show a "terminal too small" message.

### Browser pane

- Root is `start_dir`, CLI directory, or current directory.
- Entries: directories, audio files, valid CUE folders (`Album.cue/`), invalid CUE files, `.m3u`/`.m3u8` playlists. Other file types are hidden.
- Natural, case-insensitive sort; directories and CUE folders first.
- `Enter` on directory/CUE folder: descend. `Backspace`: go up, restoring the prior selection.
- `Enter` on audio/CUE track/playlist: replace queue with the playable entries at the current level starting at selection, then play.
- `a`: add selection. Directory and CUE folder expand recursively. Playlist expands to its items.
- `A`: add everything in the current location, recursively.
- `R`: rescan current directory.
- `/`: incremental filter; `Enter` accepts, `Esc` clears.
- Hidden files off by default; symlinked directories not followed by default.

### CUE handling

- A `.cue` is valid when it parses, has at least one track with `INDEX 01`, and every referenced `FILE` exists.
- Track start = `INDEX 01`; track end = next track's `INDEX 01` in the same file, or file duration for the last track. This puts a next track's pregap at the end of the previous track and keeps album continuity.
- Multi-file CUE sheets are supported.
- Windows-style backslashes and case-insensitive filename fallbacks are attempted when resolving `FILE` paths.
- Encodings: UTF-8, UTF-16 with BOM, fallback configured via `cue_fallback_encoding` (default Windows-1252).
- Inside a CUE folder: `NN. Title — Performer   duration`; missing title falls back to `Track NN`; performer falls back to sheet performer; album falls back to sheet title or CUE basename.
- Entering any CUE track plays all tracks in that CUE folder from that point.

### Playback and playlist

- Queue items: plain files, CUE tracks, playlist imports.
- Controls: play/pause, stop, next/previous, seek ±5 s, volume ±5%, mute, shuffle, repeat off/all/one.
- Auto-advance at end; repeat-one repeats; repeat-all wraps; shuffle uses a deterministic precomputed order.
- `Enter` in playlist plays the selected item; `d` removes; `K`/`J` move; `c` clears with confirmation; `g` jumps to current.
- Removing the currently playing item stops playback.
- Queue changes are persisted after each mutation; restore on launch when `restore_queue = true`; missing files are pruned with a status message.

### Playlists

- `.m3u`/`.m3u8` in the browser. `Enter` loads and plays; `a` appends.
- Relative paths resolve against the playlist's directory. Remote URLs are rejected.
- `w` prompts for a save path; default `playlist.m3u`; overwrite requires confirmation.
- CUE track extension:

  ```text
  #EXTM3U
  #EXTINF:201,Artist - Title
  #EXT-X-PLAYER2-CUE:cue=Album.cue;track=3
  Music/Album.flac
  ```

  The path line is the audio file, so other players can still play the whole file. `cue` is URL-escaped. If resolution fails, fall back to whole-file playback.

## 6. Review focus

These are the failure modes most likely to bite a real user; each has tests in the owning task.

1. **CUE boundaries.** Pregaps (`INDEX 00`), last-track duration, multi-file sheets, non-UTF-8 sheets, and Windows path separators must produce ranges that tile the album without overlaps or silent gaps. Invalid CUEs must never hide audio. (Tasks 2, 4.)
2. **Hostile/odd filenames.** Spaces, quotes, leading dashes, Unicode, and very long names must not break FFmpeg arguments, M3U round-trips, or terminal layout. Remote URLs in playlists/CUEs must be rejected. (Tasks 2, 6, 7, 10.)
3. **Missing referenced media.** A renamed/missing audio file must make the CUE invalid and visible as an error, not leave a phantom folder hiding the real file. (Task 4.)
4. **Rapid transport activity.** Fast seek/next/pause/quit sequences must not deadlock, leave orphan `ffmpeg` processes, or report a position from the wrong stream. (Tasks 7, 9.)
5. **Queue mutation during playback.** Removing current, clearing, moving, loading, and shuffling must keep selection and playback state coherent and never index out of range. (Tasks 5, 12.)

## 7. Risks and mitigations

- **FFmpeg subprocess latency / gaps:** accept short gaps in v1; decoder interface allows a persistent stream or libavcodec backend later. Same-file CUE tracks will still need future gapless work.
- **CUE encoding/path variance:** explicit fallback encoding, BOM handling, backslash and case-insensitive resolution; invalid sheets fail visibly.
- **cgo/audio device issues:** startup check with actionable error; malgo requires only `-ldl` on Linux; tests avoid real audio unless opted in.
- **Real-time audio callback:** ring uses a mutex; acceptable for v1. If glitches appear, replace with a lock-free SPSC ring.
- **UI thread blocking:** process `Start` is fast; `Close` kills and waits. Engine tests cover rapid control sequences. If needed, move control into an actor goroutine.
- **Scope creep:** v1 deliberately excludes gapless, tags, MPRIS, mouse, and library indexing.

## 8. Acceptance criteria

- `go build ./cmd/player2` succeeds with cgo enabled; `go test -race ./...` and `go vet ./...` pass.
- On a library with MP3, OGG, Opus, FLAC, ALAC, APE (manual fixture), and WAV: browse, queue, play, pause, seek, volume, next/prev, shuffle, repeat.
- A single-file FLAC/APE + `.cue` appears as `Album.cue/`; entering it lists tracks with correct durations; each track is independently seekable; Enter starts the album from that track.
- Missing/corrupt CUE is shown as an error entry and does not hide the audio file.

- No network calls; no HTTP playback; no orphan decoder processes after quit.
